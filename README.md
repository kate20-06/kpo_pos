# ПОС — Преподавательская оценка студентов

Консольное приложение на **.NET 8**, разработанное в рамках домашнего задания № 2 по курсу «Конструирование программного обеспечения». Приложение поддерживает создание студентов, преподавателей и критериев оценивания, оценивание личностных и коммуникативных качеств студентов по настраиваемым критериям, расчёт итогового результата, импорт исходных данных и экспорт ведомостей.

## Запуск и сценарии работы

Требуется .NET SDK 8.0 или новее. Команды выполняются из корневого каталога проекта:

```bash
dotnet restore
dotnet build
dotnet run --project pos.csproj
```

При запуске выбирается роль пользователя:

| Роль | Возможности |
| --- | --- |
| **Менеджер** | Создание отдельных студентов, групп студентов, преподавателей и критериев; просмотр индивидуальных и групповых результатов; импорт исходных данных и экспорт ведомостей |
| **Преподаватель** | Выставление баллов студентам закреплённых групп; повторная оценка по уже оценённому критерию не допускается |
| **Студент** | Просмотр собственных выставленных оценок, средних баллов по критериям и итогового результата |

Для демонстрации полного сценария: войти менеджером и создать критерии, преподавателя и студентов (либо импортировать данные из `examples/`), войти преподавателем и выставить оценки, затем просмотреть результаты в роли студента или менеджера и экспортировать ведомость группы. Рубрикатор при запуске пуст;

## Импорт и экспорт CSV

Импорт доступен в меню менеджера (пункт **9**). Форматы входных файлов:

| Файл | Заголовок | Содержимое |
| --- | --- | --- |
| `examples/students.csv` | `Name;Surname;Group` | Студенты и номер группы |
| `examples/teachers.csv` | `Name;Surname;Groups` | Преподаватели и группы, разделённые символом `|` |
| `examples/criteria.csv` | `Name;Text;MaxScore;Weight` | Критерии, описание, максимальный балл и вес |

Примеры содержат **30 студентов из групп 101–105, 8 преподавателей и 5 критериев личностных и коммуникативных качеств**: приятность в общении, пунктуальность, ответственность, инициативность и умение работать в команде. Каждый критерий оценивается по шкале от 0 до 10; веса критериев суммарно равны 1. Названия групп обрабатываются как строки. При создании студента или преподавателя отсутствующая группа создаётся автоматически.

Для CSV используется кодировка UTF-8 и разделитель `;`. Поддерживаются поля в кавычках, в том числе с разделителями и переводами строк. Вес допускает точку или запятую в десятичной записи. Ограничение на входной файл — **5 МиБ и 10 000 записей**.

Импорт сначала читает и проверяет все записи, затем создаёт объекты. Дубликаты **пропускаются**: студенты сопоставляются по имени, фамилии и группе; преподаватели — по имени и фамилии; критерии — по названию. Сравнение выполняется без учёта регистра и крайних пробелов. После импорта выводится число добавленных и пропущенных записей. Ошибки формата не приводят к частичному добавлению; полная транзакционность при исключительных сбоях хранилища не обеспечивается.

Экспорт ведомости группы выполняется менеджером (пункт **3**). Выходной CSV содержит имя и фамилию студента, средние баллы по критериям и итоговый процент. Используются UTF-8 с BOM, `;` и экранирование текстовых полей.

## Доменная модель и DDD

**Единый язык предметной области (Ubiquitous Language):** студент (`Student`), преподаватель (`Teacher`), группа (`Group`), критерий (`Criterion`), рубрикатор (`Rubric`), оценка (`CriterionGrade`), оценивание студента (`StudentEvaluation`), итоговый результат.

- **Сущности (Entities):** `Student`, `Teacher` и `Group` имеют идентификаторы `Guid`. `StudentEvaluation` идентифицируется по `StudentId` и выступает корнем агрегата оценок одного студента.
- **Value Object:** `CriterionGrade` — неизменяемый `record` с критерием, идентификатором преподавателя и баллом. Состояние оценки после создания не изменяется.
- **Агрегат:** `StudentEvaluation` добавляет оценки только при наличии *того же экземпляра* критерия в текущем `Rubric` и запрещает повторную оценку одного критерия тем же преподавателем.
- **Инварианты:** непустые имена и идентификаторы; `MaxScore > 0`, конечный `Weight > 0`, `0 ≤ Score ≤ MaxScore`; проверка принадлежности критерия рубрикатору; уникальность студентов внутри группы, преподавателей по имени и фамилии и критериев по названию. `TeacherFacade` дополнительно проверяет принадлежность студента группе преподавателя.
- **Domain Service:** `EvaluationCalculator` вычисляет средний балл по критерию среди выставленных оценок и итоговый процент как нормализованную средневзвешенную сумму по **оценённым** критериям. При отсутствии оценок итог не определён (`null`).
- **Repository:** `IStudentEvaluationRepository` — порт хранения агрегатов; `InMemoryStudentEvaluationRepository` — его реализация.

Принадлежность студента группе представлена через `Student.GroupId`; второй изменяемый список студентов внутри `Group` не хранится.

## Архитектура и зависимости

Используется **облегчённая Clean Architecture** с логическим разделением на четыре слоя:

```text
ConsoleUI        → Application → Domain
Infrastructure  → Application / Domain
```

| Слой | Назначение |
| --- | --- |
| `Domain/` | Сущности, Value Object, агрегат, рубрикатор, доменные инварианты и расчёт итога |
| `Application/` | Фасады, фабрики, `SchoolImportService` и интерфейсы для работы с хранилищами и файлами |
| `Infrastructure/` | Хранение в памяти, CSV-чтение и CSV-экспорт |
| `ConsoleUI/` | Консольные сценарии, маршрутизация по ролям, вывод отчётов, сборка зависимостей |

`SchoolFacade` предоставляет операции административного управления и делегирует импорт в `SchoolImportService`. Последний выполняет проверку набора записей и создание объектов через фабрики; чтение формата скрыто за `ISchoolDataReader`. `TeacherFacade` координирует оценивание, `ReportFacade` — получение и экспорт результатов.

**DI:** граф зависимостей настраивается в `ConsoleUI/DependencyInjection.cs` (composition root). `Rubric`, `ISchoolData` и репозиторий оценок зарегистрированы как singleton; фасады и сценарии — transient. `Application` зависит от интерфейса `ISchoolData`, а списки хранятся в реализации `InMemorySchoolData` внутри `Infrastructure`.

Слои расположены в одном `.csproj` — архитектурные границы поддерживаются соглашениями и интерфейсами, но не отдельными компилируемыми сборками.

## Паттерны GoF и принципы SOLID

| Группа GoF | Паттерн | Применение |
| --- | --- | --- |
| Порождающие | **Factory Method** | `Factory<T>.Create()` задаёт общий алгоритм создания и регистрации; `StudentFactory` и `TeacherFactory` реализуют `CreateEntity()` и `Save()` с учётом правил привязки к группам |
| Структурные | **Facade** | `SchoolFacade`, `TeacherFacade`, `ReportFacade` скрывают взаимодействие фабрик, хранилищ, агрегатов и сервисов за высокоуровневыми операциями |
| Поведенческие | **Strategy** | `IUserScenario` и три реализации (`StudentScenario`, `TeacherScenario`, `ManagerScenario`) позволяют `ConsoleController` выбирать сценарий по роли |
| Поведенческие | **Template Method** | `Factory<T>.Create()` определяет общий алгоритм создания сущностей: валидацию входных данных, проверку ограничений, получение или создание групп, создание и сохранение объекта. `StudentFactory` и `TeacherFactory` переопределяют отдельные шаги алгоритма (`ValidateGroups()`, `ValidateCreation()`, `CreateEntity()`, `Save()`), сохраняя общую последовательность операций. |

**SOLID:** ответственность разделена между предметной областью, сценариями, импортом и файловыми адаптерами (**SRP**); интерфейсы допускают замену реализации хранения и формата экспорта (**OCP**, **DIP**); порты специализированы (**ISP**). Фабрики реализуют общий алгоритм, но типовые ограничения на число групп различаются у студента и преподавателя; это учитывается как различие доменных контрактов, а не универсальная взаимозаменяемость всех фабрик (**LSP**).

## Тестирование

В проекте предусмотрены два уровня автоматических проверок:

| Проект | Назначение |
| --- | --- |
| `tests/PosUnitTests/` | Независимые тесты xUnit: доменная модель, инварианты, расчёты, фабрики, хранилища, фасады, импорт/экспорт CSV, консольный ввод и DI |
| `tests/PosChecks/` | Сквозные проверки согласованной работы нескольких компонентов, включая полный путь оценки, импорт и экспорт |

Запуск:

```bash
dotnet test tests/PosUnitTests/PosUnitTests.csproj
dotnet run --project tests/PosChecks/PosChecks.csproj
```

Сбор покрытия unit-тестов:

```bash
dotnet test tests/PosUnitTests/PosUnitTests.csproj --collect:"XPlat Code Coverage"
```

Проверки включают граничные баллы, неверные идентификаторы, дубликаты, неконечные веса, отсутствие частичного добавления при ошибочных входных данных, разбор CSV и обработку вывода. Файловые тесты с временными CSV проверяют компонент вместе с файловой системой. Интерактивные сценарии с реальным пользователем требуют отдельной ручной проверки. 

## Ограничения

Приложение рассчитано на один консольный процесс; данные хранятся в памяти и не сохраняются между запусками. Выбор роли не является аутентификацией: в рабочей системе требуется проверка личности и прав доступа на уровне операций. Исправление и удаление выставленных оценок, пересдачи и работа с несколькими курсами не реализованы; они вынесены за рамки базового сценария. Совпадение имени и фамилии в одной группе рассматривается как дубликат студента, а совпадение данных преподавателя — как дубликат преподавателя.
